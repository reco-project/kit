# Calibration

Calibration turns two independent cameras into one aligned panorama, producing a `match.json` the engine reads. It is the biggest quality lever and the most room to improve: lenses vary and can shift slightly over time, so a seam that has drifted usually means it is worth recalibrating.

There are two stages: **per-camera lens intrinsics**, then the **stereo rig** that relates the two.

## Stage 1 - lens intrinsics (per camera)

The fisheye lens distortion has to be measured before the two views can be aligned. Record a checkerboard, then solve for the KB4 (Kannala-Brandt) model: `fx, fy, cx, cy` and four distortion coefficients.

**Recommended for now: [Gyroflow](https://gyroflow.xyz).** Its lens-calibration workflow is the easiest way to get a solid profile today, and `record_lens_calib.sh` captures footage tuned for it. The repo's `calib_v2.py` solver is an alternative. Reco's engine ([video-stitcher](https://github.com/reco-project/video-stitcher)) will add native lens-calibration tools over time.

1. **Record** a checkerboard at the sensor's native square-pixel mode (4032x3040), all-intra, low fps so every frame is a sharp still:
   ```
   ./tools/record_lens_calib.sh [seconds] [sensor-id]
   ```
   While it records, walk the board through ~15-20 poses. **Fill the frame edges and especially the corners** - that is where distortion lives and where the solve is otherwise unconstrained. Keep it flat, rigid, and in focus.

2. **Solve** for the lens profile:
   ```
   ./tools/calib_v2.py <frame_dir> <COLSxROWS> <yscale> <out_dir>
   ```
   `calib_v2.py` detects corners at full resolution (downscaling throws away precision) and drops bad views iteratively. Use `calib_diag.py` to inspect the detections and the corner-coverage map - if corners never reach the image edges, `cx` and the distortion terms stay unconstrained and RMS will be high.

Both lenses are the same model, so you can calibrate one sensor and reuse the profile, or calibrate each.

## Stage 2 - stereo rig (the two cameras together)

This relates the left and right views. It uses hand-clicked correspondences, which is low-tech but robust on a field scene.

1. Capture one stereo frame **undistorted** using the engine's debug output (`reco camera ... --debug-dir <dir>`), which writes `frame_00_left.png` / `frame_00_right.png` already in the L/R calibration convention.

2. **Click correspondences** - the same real-world point in both views. The hand-click capture tool is being finalized and lands with the next update; it writes a `clicks.json` of ~12-25 well-spread pairs (corners of the field, distinct objects across the overlap) in the optimizer/plane format.

3. **Solve into a `match.json`:**
   ```
   ./tools/clicks_to_match.py <clicks.json> <lens_profile.json> <out_match.json> [rig_tilt_deg]
   ```
   This runs the engine's `optimize_points` solver on the clicked pairs and assembles a deployable `match.json` from the solution + the lens profile + the rig tilt.

## Tools

| Tool | Purpose |
|---|---|
| `record_lens_calib.sh` | Capture a checkerboard at native res for lens calibration. |
| `calib_v2.py` | Precision KB4 fisheye lens solve (full-res corners, iterative drop). |
| `calib_diag.py` | Inspect detections + corner coverage to diagnose a bad solve. |
| `clicks_to_match.py` | Solve clicks + lens profile into `match.json`. |

The solver (`optimize_points`) and the `--debug-dir` undistorted frames come from the engine, [video-stitcher](https://github.com/reco-project/video-stitcher) - build it first.

## ISP color override

`camera_overrides_imx477.isp` is a custom IMX477 ISP tuning that corrects a purple / no-IR-cut color cast some modules show. It is hand-made and rough, not a high-standard calibration, but a usable starting point. Improve or replace it as you like.

The file is generated by NVIDIA's camera-tuning tool, so it keeps NVIDIA's header; the tuning values in it are ours. It ships here for interoperability and is not covered by this repository's Apache-2.0 / CERN licenses - NVIDIA's terms govern the file itself.
